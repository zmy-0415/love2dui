# 素材方案：先算、再借、最后才画

> 这份文档回答一个问题：一个人怎么给《裂界》这种体量的游戏准备美术。
> 配套代码在 `game/art/`，出图工具在 `tools/artsheet.lua`，可跑预览是
> `love . art_preview`。

---

## 1. 先算一笔账，再说怎么做

手绘方案在这个项目上不可行，不是懒，是数量级不对。按设计文档的规划：

| 资产 | 数量 | 说明 |
|---|---|---|
| 武器外观 | **数千种** | 刃 5 档 × 柄 5 档 × 芯 5 档 × 6 类 = 750 种组合，再乘 32 条词条的视觉差异 |
| 怪物 | 40~60 种 | 9 层 × 每层 4~6 种，加精英词缀变体、事件波次专属 |
| 角色动作 | 5 状态 × 正反 | idle / run / attack / hurt / dead |
| Boss | 5 只 | 每只 3 阶段 + 部位破坏 |
| 地形瓦片 | 9 层 × 每层 8~12 种 | 加边缘连接变体（autotile）后是数百张 |
| 特效 | 命中、暴击、破韧、元素、死亡 | 每层元素一套 |

单是「每个角色 5 状态 × 48 帧」这一行，60 个怪就是 14,400 帧。
按一个有经验的美术每天产出 15 帧计算，需要 **960 个工作日**。
这不是预算问题，是物理上做不完。

所以策略不是「怎么画得更快」，而是 **「哪些东西根本不该画」**。

---

## 2. 三层策略：把资产按「数量」和「被注视时长」分开放

| 层 | 占比 | 手段 | 覆盖什么 | 为什么放在这一层 |
|---|---|---|---|---|
| **L1 程序化** | ~70% | 骨架 + 皮肤参数 + 参数化轮廓 | 全部角色动作、怪物、Boss、**全部武器**、特效 | 数量大、变化多、玩家不会盯着看每一帧 |
| **L2 CC0 素材** | ~20% | 现成开源像素包 | 地形瓦片、UI 图标、装饰物、粒子贴图 | 手绘最费工，但对风格统一最不敏感 |
| **L3 委托/AI** | ~10% | 外包画师 + 生成工具 | 玩家角色、5 只 Boss 立绘、标题画面、过场 | 玩家注视时间最长、决定第一印象 |

**分界线是「玩家会盯着看多久」**，不是「画起来难不难」。
玩家会盯着自己的角色看 40 小时，值得花钱；不会盯着第 37 把剑的刃纹看，不值得。

## 3. 程序化管线：五个模块

代码已经落地在 `game/art/`，全部零外部依赖、零贴图文件。

```
palette.lua    受限调色板：材质 → 五阶色（dark/base/light/edge/glow）
rng.lua        确定性随机：同一把武器永远长同一样子
rig.lua        骨架：节点树 + 世界角约定 + 描边 + 顶光
creature.lua   四类骨架族（人形/爬行/软体/飞行）+ 动作曲线
boss.lua       分节躯体 + 唯一发光弱点 + 阶段变化
weapon.lua     刃 + 柄 + 芯组装 → 参数化轮廓
```

### 3.1 骨架，而不是帧

角色的每个动作都是**关节角度的函数**，不是一组图片。

```lua
-- 攻击：前摇抬刀 → 判定挥出 → 后摇收势
pose.arm_near = kf(u, { {0, 0.16}, {0.38, -2.05}, {0.52, 1.35}, {0.72, 0.55}, {1, 0.16} })
```

这带来三个只有骨骼能做的事：

1. **攻速词条改时间轴**：`+12% 攻速` 就是让 `u` 走快一点，不用重画 48 帧。
2. **帧数据可视化**：前摇 6 帧、判定 3 帧、后摇 10 帧，直接对应曲线的三段。
3. **武器挂点自动跟随**：`Rig.tip(skel, pose, "hand_near")` 算出刀在哪儿，
   刀光、粒子、判定框都从这里出，不会和动画对不上。

### 3.2 骨架族：四类骨架覆盖整个生态

| 骨架 | 用在哪 | 节点数 |
|---|---|---|
| `humanoid` | 玩家、骷髅矿工、腐化教徒、精英人形 | 17 |
| `crawler` | 矿虫、腐化蜈蚣、深渊爬兽 | 19 |
| `blob` | 史莱姆、腐化团、岩浆泡 | 7 |
| `flyer` | 洞穴蝠、虚空浮眼、熔岩鸟 | 6 |

一个新怪物 = 选一族骨架 + 改 5 个颜色 + 3 个尺寸系数：

```lua
Creature.crawler({ shell = "void", leg = "crystal", size = 1.25 })  -- 精英变体
```

精英词缀（爆裂/吸血/分裂/护盾/迅捷/荆棘）不需要新贴图，
走 `Palette.rotate` 换色相 + 叠加一层发光强度即可。

### 3.3 武器：唯一「必须」程序化的部分

这是整份方案里没有替代方案的一块。设计文档规定武器 = **刃 + 柄 + 芯**，
玩家在铁砧前把铜刃换成炎铁刃的那一刻，这把武器的形状是**世界上第一次存在**的——
不存在对应的贴图，图集里也不可能有位置。

所以武器是算出来的：

```lua
local vis = Weapon.build({
    class = "great", bladeTier = 5, hiltTier = 4, coreTier = 4,
    bladeMat = "void", affixes = { "void", "crit" },
})
Weapon.draw(g, vis, x, y, angle, scale)
```

`build` 是纯函数：同样的 spec（几个数字）永远得到同样的轮廓。
**存档只需要存这几个数字**，不用存图形。

顺带解决了一个常见麻烦：武器判定框直接复用刀刃多边形，
不用另外维护一套碰撞数据，也就不会出现「看起来打到了却没判定」。

### 3.4 Boss：用「节」组织，不是用「图」

Boss 和小怪的区别不在精细度，而在 **玩家能不能一眼看懂要打哪儿**。
石喉用独立节点拼躯体：

- 头节最大、有颚、有三只眼 → 玩家本能会打这里
- 中节负责「这怪物很长」的体量感
- **尾节是全身唯一强发光的部分** → 视觉上最吸引人，但它才是真弱点

这是刻意的引导与反转：先让玩家打错，再让他学会。
三个阶段只改发光强度（`Boss.applyPhase`），不换任何图形。

### 3.5 一致性靠规则，不靠人

程序化最容易翻车的地方是颜色：每个物件单独挑色，几百个摆在一起就脏。
所以调色板只允许从材质色派生，派生规则写死：

```
每个材质一条色相轨道 → dark / base / light / edge / glow 五阶
```

想换整体气氛（血月、熔核、深渊）只改 `Palette.setAmbient()` 一个数，全局跟着变。

形状语言同样是规则：圆 = 生命，方 = 矿物/机械，三角 = 威胁。
玩家不用读文字就能分出「这个能打」和「这个能挖」。

## 4. 各类资产的具体做法

### 4.1 人物

| 项 | 做法 |
|---|---|
| 基准尺寸 | 26~28 逻辑像素高（约 4 头身），画在 480×270 的逻辑画布上 |
| 动作 | idle / run / attack（三段）/ hurt / dead，全部是曲线 |
| 装备外观 | 护甲 = 换 `cloth` / `metal` 材质色 + `bulk` 体型系数；头盔是可选节点 |
| 朝向 | 单侧绘制 + 水平镜像（`g.scale(-1,1)`），不做 8 方向 |

**为什么不做 8 方向**：8 方向意味着 8 倍工作量，而 2D 侧视动作游戏里
玩家 90% 时间在看左右两侧。上下坡用倾斜角补偿，不做独立素材。

### 4.2 怪物

按层分配骨架族，保证每层有「地面 / 空中 / 特殊」三种压迫方式：

| 层 | 地面 | 空中 | 特殊 |
|---|---|---|---|
| 地表 | crawler（矿虫） | flyer（蝠） | — |
| 腐化裂隙 | blob（腐化团） | flyer | 孢子云（特效） |
| 熔核 | crawler（炎铁爬兽） | flyer（熔岩鸟） | blob（岩浆泡） |
| 深渊 | crawler（爬兽） | flyer（浮眼） | 分身（同骨架 + 半透明） |

### 4.3 武器

| 类别 | 轮廓特征 | 判定形态 |
|---|---|---|
| sword 剑 | 直刃，末端收尖 | 扇形 90° |
| great 大剑 | 前段等宽，末端斜切 | 扇形 130°，慢 |
| axe 战斧 | 中前段鼓出 | 月牙 |
| spear 长枪 | 细长，仅前 28% 收尖 | 细长矩形 |
| hammer 战锤 | 等宽平头 | 圆形 |
| dagger 短刃 | 短、窄、弯 | 小扇形，快 |

五档的差异是**能看出来的**：长度 13→21.5、弯曲 0.10→0.55、护手变复杂、
刃口出现波纹、宝石变大。测试里有一条断言专门守着「档位越高刃越长」。

### 4.4 地形（L2，走 CC0）

地形是全套资产里唯一建议直接买/借的：手工画 autotile 的边缘连接变体极费工，
而玩家对「这块石头画得好不好」的敏感度远低于对角色动作的敏感度。

- 16px 瓦片，每层一套 8~12 种基础块
- 边缘连接用代码做（4-bit / 8-bit autotile），素材只需要 16 张掩码图
- 候选来源见第 6 节

### 4.5 特效（纯代码）

| 效果 | 做法 |
|---|---|
| 刀光 | 取武器最近 3 帧的刀尖轨迹，画成渐隐拖尾多边形 |
| 命中 | 白闪（`tint`）+ 顿帧（hit-stop）+ 火花粒子 |
| 暴击 | 屏幕轻微缩放 + 径向白线 |
| 破韧 | 紫色裂纹叠加 + 短促的屏幕震动 |
| 元素 | 沿刀身撒粒子，颜色取自芯的材质 |

这些全部是代码，没有一张贴图，帧率也更可控。

### 4.6 UI 图标（L2 + 少量手绘）

道具/材料图标约 60 个。程序化画不出好看的图标（形状太复杂、尺寸太小），
建议 CC0 图标包打底 + 20 个核心图标手绘。

## 5. 渲染规格

| 项 | 值 | 原因 |
|---|---|---|
| 逻辑分辨率 | 480×270 | 16:9，3x → 1440×810，4x → 1920×1080 |
| 缩放 | 最近邻整数倍 | 保持像素边缘，不糊 |
| 人物高度 | 26~28 px | 屏幕上约占 1/10 高，能放 10 个不挤 |
| 描边宽度 | 1.0~1.5 px | 暗背景下靠轮廓撑住形体 |
| 光源方向 | 统一左上 | 顶光带固定画在节点上沿 |
| 色板 | 24 材质 × 5 阶 | 见 `palette.lua` |

## 6. 授权与合规

**只用 CC0，CC-BY 必须登记，来源不明的打包一律不用。**

| 来源 | 许可 | 适合拿什么 |
|---|---|---|
| Kenney（kenney.nl） | CC0 | UI、图标、基础瓦片、音效 |
| Pixel Frog（itch.io） | CC0 | 角色/怪物像素包（可作参考与备选） |
| LimeZu（itch.io） | 部分 CC0 / 付费 | 场景装饰、室内家具 |
| OpenGameArt（筛 CC0） | 视条目 | 瓦片、背景、特效贴图 |
| 自制 / 委托 | 自有 | 玩家角色、Boss、标题 |

规则：
- 引入任何外部素材，必须在 `CREDITS.md` 记一行：来源、作者、许可、链接
- CC-BY 素材可以做，但要能一眼找到署名位置（游戏内「关于」页）
- 商用前跑一遍许可复核，尤其是「免费素材站」的二次分发包

## 8. 验收与回归

美术是算出来的，所以它可以被测试、被比对：

```bash
luajit tools/artsheet.lua sheet.bmp 2   # 出一张素材总览图（不需要显卡）
luajit tests/full.lua                    # 含 34 条美术断言
```

已建立的断言（`tests/art.lua`）：

- 所有材质色阶都在 0~1（曾经因为溢出把橙红烧成青色）
- 同种子必须得到完全相同的武器轮廓（存档只存种子才成立）
- 刃长随档位单调递增（数值成长要能看出来）
- 攻击姿势下握刀手明显移位（否则武器不会跟着挥）
- Boss 阶段推进后弱点变暗（这是「它变了」的唯一提示）
- 一组素材一帧的绘制调用 < 400（防止「加了细节，帧率崩了」）

`tools/softraster.lua` 是一个纯 Lua 软件光栅器，实现了 `love.graphics`
的一个子集，能在没有显卡的机器（包括 CI）上把同样的绘制代码渲染成图片。
这就是为什么这套美术方案可以在没有 OpenGL 的环境里开发和验收。

## 9. 什么时候必须换成手绘

程序化不是万能，以下几种情况**应该**花钱：

1. **玩家角色**：会被盯着看几十小时，值得 2~3 套皮肤的手绘
2. **5 只 Boss 的立绘/出场**：第一印象，决定视频能不能传播
3. **觉醒武器**：每把都是唯一获得物，玩家会截图
4. **标题画面与过场**：营销素材

换的时候不需要改代码：`game/art/` 的绘制接口是「给定 x/y/朝向/姿势就画」，
把手绘帧接进同一个接口，上层战斗逻辑一行都不用动。
